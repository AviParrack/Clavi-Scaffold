# Commit Style

Commits are running commentary, not changelog entries. Future historians should find them interesting.

**Do:**
- Informative and warm — personality welcome
- Substance: what changed and why, not just what files
- Use emoji sparingly as status markers (same visual language as CLAUDE.md)
- State-of-mind when genuine ("genuinely proud of this one", "2am and it shows")

**Don't:**
- "fix bug", "update file", "misc changes"
- Generic or robotic tone
- Overly long — if it needs a paragraph, use the commit body

**Easter egg convention:** commits in a series may carry structural leaking — fragments of the workspace philosophy surfacing naturally.
